打印了 11 处，为何只有 10 个任务？

长图

答

结论

同一 :compileJava 被两个父任务依赖，所以打印了两处。

  1. 位置 5、7 指向同一任务身份。
  2. 根工程与 includedProject 的同名任务分开计数。
  3. 星号表示先前已打印，不记录执行次数。1

适用于固定上游测试 expected计划依赖投影未运行 Gradle

1

每个打印位置指向谁？

点任务路径可定位图中身份。位置 5 和 7 会指向同一个 compileJava。身份按完整 path 判断。2

打印位置完整 task path原树父位置对应的任务标记
1:dependsOnIncluded入口首次打印
2:assemble:dependsOnIncluded首次打印
3:jar:assemble首次打印
4:classes:jar首次打印
5:compileJava:classes首次打印
6:processResources:classes首次打印
7:compileJava:jar* · 与位置 5 同一身份
8:includedProject:taskInIncludedProject:dependsOnIncluded首次打印
9:includedProject:build:includedProject:taskInIncludedProject首次打印
10:includedProject:assemble:includedProject:build首次打印
11:includedProject:check:includedProject:build首次打印

11 个打印位置减去 1 个重复引用，得到 10 个任务身份。此例的 compileJava 是叶子；星号没有藏起后续任务。3

2

哪两个父任务共享它？

classes 和 jar 的依赖箭头都指向同一个 compileJava。所有箭头都表示父任务依赖目标任务；不是执行先后。

图的结构
  • :dependsOnIncluded t1
  • :assemble t2
  • :jar t3
  • :classes t4
  • :compileJava t5
  • :processResources t6
  • :includedProject:taskInIncludedProject t7
  • :includedProject:build t8
  • :includedProject:assemble t9
  • :includedProject:check t10
  • t1 → t2
  • t2 → t3
  • t3 → t4
  • t4 → t5
  • t4 → t6
  • t3 → t5
  • t1 → t7
  • t7 → t8
  • t8 → t9
  • t8 → t10

根工程的 :assemble 与 :includedProject:assemble 是不同身份。图中每个标签均为完整 task path，表格和节点说明保留原打印位置。
