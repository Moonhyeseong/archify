结论

图中保留假分支的 - a，并不证明程序执行过它。这里读取官方测试的静态期望，不是一次程序运行。

  1. 完整输入：a = 1; a + 1 if a else - a。
  2. 四个 a 是一个定义和三次读取，不能按同名合并。
  3. expected 三次展开 IfExp，图里仍是同一个表达式节点。
  4. 这里只投影以模块局部定义 a 为根的 use-chain。

适用于固定官方测试期望；未运行 Beniget/Python；非完整 AST、CFG 或执行证据

四次 a 如何汇入同一个表达式？

图的结构
  • 定义 a def-a
  • 读取 a · 条件 load-test
  • 读取 a · 真分支 load-body
  • 读取 a · 假分支 load-else
  • a + 1 binop
  • - a unaryop
  • 条件表达式 ifexp
  • def-a → load-test · use
  • def-a → load-body · use
  • def-a → load-else · use
  • load-test → ifexp · use
  • load-body → binop · use
  • binop → ifexp · use
  • load-else → unaryop · use
  • unaryop → ifexp · use

箭头只表示 use，没有求值先后或已发生调用。局部关系借用原生图展示，不是业务架构。1
