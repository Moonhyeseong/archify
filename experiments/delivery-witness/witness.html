结论

msgId=0 在 t=15 ms 有两条 deliver 记录，seq 分别是 12 和 15。

  1. 同一时刻还记录了两个 raw state.patch：seq=14 的 got=1、seq=17 的 got=2。
  2. 只看后一个 patch 会漏掉中间记录；这些片段不是完整状态快照。

适用于官方 Moirae 模拟 fixture 选段，非本次运行、非生产 trace。仅按原始 msgId/seq 关联；不由相同 t 或相邻行推断因果。

1

两条投递记录，共用一次 send 的端点

图的结构
  • Node 1 n1
  • Node 2 n2
  • n1 → n2 · msgId=0 / seq=12 / t=15ms / dup: not supplied
  • n1 → n2 · msgId=0 / seq=15 / t=15ms / dup=true

箭头仅表示 deliver。Node 1→Node 2 从 L7 的同 msgId send 投影；deliver 原行没有 from/to。纵向间隔仅为阅读次序。

2

按原 seq 读，别把 t 当事件身份

原始位置 / 事件模拟时间字段摘录
sendL7 · seq=5t=10 msfrom=1 · to=2 · msgId=0
deliverL14 · seq=12t=15 msmsgId=0 · dup: not supplied
raw patchL16 · seq=14t=15 msnode=2 · patch={"got":1}

raw patchL19 · seq=17t=15 msnode=2 · patch={"got":2}

seq=13 / L15 与 seq=16 / L18 是 Node 2 另发 pong 的记录，表中未展开，完整原行在下方。state.patch 没有 msgId；这里不声称某条 deliver 导致某个 patch。

3

完整选中原行与边界

  • 原文件共 98 行；本页未展示其他消息、初始完整状态及后续故障。完整 engine.jsonl 随实验保存。
  • msgId=0 在完整 fixture 中有 1 send、2 deliver、0 drop；这不是协议一般保证。
  • 第一条 deliver 缺少 dup 字段，不能补成 false。第二条原文为 dup=true。
  • 不调用上游 stateAt(node,t)，不折叠 patch、不把 null 解释成业务 null；上游 patch 合同中 null 表示删除字段。
  • 这里只核对内容表达；不据此声称用户收益或人类、跨浏览器、生产验收。本轮 browser-check 结果见实验摘要。
