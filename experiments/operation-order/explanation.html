结论

没有合法顺序。 两次读取的实时先后与寄存器模型要求组成矛盾。

  1. 上游 Porcupine README 的说明例；不是自然采集，也不是本轮运行。
  2. README 声明 checker 返回 false；本页没有执行 Porcupine。1
  3. 以下位置是事件顺序编号，不是时间、时长或测量。

适用于上游说明例顺序位置非时间checker结果为README声明

1

六条原始事件

寄存器初态为 0。put(v) 写入 v；get 必须返回当前值且不改变状态。输入中的 true, 0 是 get 的输入，输出另见 return。1

位置客户端 / ID类型原值
1C0 / 0CallregisterInput{false, 200}
2C1 / 1CallregisterInput{true, 0}
3C1 / 1Return200
4C2 / 2CallregisterInput{true, 0}
5C2 / 2Return0
6C0 / 0Return0

W 是 C0 的 put；R200 是 C1 的 get；R0 是 C2 的 get。W 覆盖两个读取的调用与返回，但没有记录内部写入瞬间。

2

三句话解释矛盾

  1. 实时：R200 返回后 R0 才调用，因此 R200 必须排在 R0 之前。
  2. 模型：初态为 0 且只有 W 写入 200，R200 返回 200 要求 W 排在 R200 之前。
  3. 模型：R0 返回 0 要求 R0 排在 W 之前；三条要求互相矛盾。
3

约束图：箭头表示必须排在前面

这是顺序约束环，不是观察到的调用环、死锁或因果环。模型边是对这个完整示例的推导，不是上游记录的消息或内部执行。

图的结构
  • W · put 200 write
  • R200 · get 200 read200
  • R0 · get 0 read0
  • write → read200 · 模型：读200
  • read200 → read0 · 实时：先返回
  • read0 → write · 模型：读0
4

本实验独立枚举

只列出满足 R200 在 R0 之前的全部三个排序，逐项模拟上面的寄存器模型。以下是本实验复核，不是运行 Porcupine，也不是通用 checker。

候选顺序首个不符
W → R200 → R0R0 读到 0，但状态为 200
R200 → W → R0R200 读到 200，但状态为 0
R200 → R0 → WR200 读到 200，但状态为 0

其他三个排列违反已记录的实时先后。此结论依赖示例的完整三操作、初态和模型，不说明系统内部执行或故障原因。
