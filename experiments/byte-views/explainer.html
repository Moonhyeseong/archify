四个 flags 为什么不增加 IHDR 长度？

长图

答

结论

四个 flags 重读 type 内的四位。IHDR 仍是 25 字节：4 + 4 + 13 + 4。

  1. length = 13 只计 data，不是整个 chunk 长度。
  2. type 占 4 字节；四个 flags 都在它的 32 位以内。
  3. 树按存储字段和解释视图组织，节点数不能当字节数。

适用于固定 97B PNGIHDR 局部独立字节观察未运行 fq

1

哪些是存储，哪些是解释？

图的结构
  • IHDR · 25 B ihdr
  • length · 4 B length
  • type · 4 B type
  • data · 13 B data
  • CRC · 4 B crc
  • ancillary = false ancillary
  • private = false private
  • reserved = false reserved
  • safe_to_copy = false safe_to_copy
  • ihdr → length
  • ihdr → type
  • ihdr → data
  • ihdr → crc
  • type → ancillary
  • type → private
  • type → reserved
  • type → safe_to_copy

IHDR 到四字段表示存储分解；type 到 flags 表示重叠解释。第二层不增加存储。1

25 字节怎样对账？

存储字段原文件 byte 区间大小固定输入观察
length[8,12)4 B00 00 00 0d，大端值 13
type[12,16)4 B49 48 44 52，ASCII IHDR
data[16,29)13 B仅记录原字节，不解码像素
CRC[29,33)4 Bd4 9f 76 ed，本轮不重算
合计[8,33)25 B其余 72 B 保留在完整输入，未展开

完整文件 97 B：signature 8、IHDR 25、PLTE 24、IDAT 28、IEND 12。上游 golden 报告这些范围与 CRC valid；这是上游既有期望，不是本轮 fq 实跑结果。2

四位具体在哪里？

所有区间为半开区间。bit offset 等于 byte offset 乘 8，再加最高位起算索引。type 对应 bit [96,128)，四位全部落在其中。golden 的 0xc.2 是 byte 12 加 2 bits，不是十进制 12.2 字节。
